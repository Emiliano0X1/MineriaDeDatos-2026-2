Pregunta sobre ETL: Durante el proceso de Extract y Transform diario, descubres que la aplicación web transaccional guarda la máscara visual de la radiografía en base64 (una cadena de texto de 2 MB por fila). ¿Por qué sería un error catastrófico cargar (Load) ese string gigantesco en la Tabla de Hechos y cómo lo resolverías en tu tubería de datos?

- La razón por la cual sería un error catastrófico es debido a que en la tabla de hechos se registra cada evento diario y, al tener un input de 2 MB por fila, rompe el almacenamiento y la memoria RAM, afectando el rendimiento de las consultas; además de que rompe con el modelo OLAP, ya que la tabla de hechos solo debe tener las llaves foráneas y métricas numéricas. Para poder solucionarlo se puede utilizar una llave foránea que sea la que relacione a la máscara como (ID_Mascara) para mantener la tabla de hechos limpia y, para evitar sobrecargar la dimensión de máscara, utilizar un blob de almacenamiento externo y guardarlo como imagen para poder solo guardar la URL y el ID en las tabla de mascara.
